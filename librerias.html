¿Qué es una librería y qué es un toolkit?

Librería (biblioteca)

Una librería es un conjunto de código ya escrito y probado (funciones, clases, métodos) que se puede reutilizar en distintos proyectos para realizar tareas específicas, sin programarlas desde cero. El programador llama a la librería cuando la necesita. Ejemplo: Retrofit para peticiones web, Glide para imágenes.

Toolkit (kit de herramientas)

Un toolkit es un conjunto más amplio de herramientas, librerías, componentes de interfaz, utilidades y a veces documentación y emuladores, pensado para construir aplicaciones en una plataforma o con un enfoque determinado. Normalmente ofrece una estructura completa de trabajo. Ejemplo: Android SDK + Jetpack, Flutter, React Native.

En Android se agregan en el archivo build.gradle (módulo app), por ejemplo:

dependencies {
    implementation("com.squareup.retrofit2:retrofit:2.9.0")
    implementation("com.github.bumptech.glide:glide:4.16.0")
    implementation("androidx.room:room-runtime:2.6.1")
}

Las versiones cambian con el tiempo; conviene revisar la más reciente en la documentación de cada librería.

Diferenciar toolkits aplicables a la programación de aplicaciones móviles

Toolkit Lenguaje Plataformas Características
Android SDK + Jetpack Kotlin, Java Android Toolkit nativo oficial de Google. Máximo acceso al hardware y mejor rendimiento. Se usa con Android Studio.
iOS SDK (Xcode, SwiftUI/UIKit) Swift, Objective-C iOS, iPadOS Toolkit nativo de Apple. Requiere una Mac para desarrollar.
Flutter Dart Android, iOS, web, escritorio Multiplataforma de Google. Una sola base de código, interfaz basada en widgets y buen rendimiento.
React Native JavaScript / TypeScript Android, iOS De Meta. Usa componentes nativos y React; ideal si ya se sabe JavaScript.
.NET MAUI (Xamarin) C# Android, iOS, Windows, macOS De Microsoft. Sucesor de Xamarin, se integra con el ecosistema .NET.
Ionic / Capacitor HTML, CSS, JavaScript Android, iOS, web Apps híbridas basadas en tecnologías web dentro de un contenedor nativo.
Kotlin Multiplatform Kotlin Android, iOS y otros Comparte la lógica de negocio entre plataformas y mantiene interfaz nativa.

Nativo vs. multiplataforma: las herramientas nativas dan el mejor rendimiento y acceso completo al dispositivo, pero requieren desarrollar una app por plataforma. Las multiplataforma ahorran tiempo y costo al compartir código, aunque pueden tener limitaciones con funciones muy específicas del dispositivo.
