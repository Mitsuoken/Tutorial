¿Qué es la depuración y la seguridad?

Depuración (debugging)

La depuración es el proceso de encontrar, analizar y corregir errores (bugs) en el código de una aplicación. Consiste en ejecutar la app de forma controlada, observar qué valores tienen las variables, qué línea se ejecuta y por qué algo no funciona como se espera.

Tipos de errores comunes:

  • De sintaxis: el código está mal escrito y no compila.
  • De ejecución: la app se cierra al correr (por ejemplo NullPointerException).
  • Lógicos: la app corre pero da un resultado incorrecto.

Seguridad

La seguridad en aplicaciones móviles es el conjunto de prácticas y mecanismos para proteger los datos del usuario, el código y la comunicación con servidores contra accesos no autorizados, robo o modificación de información. Busca garantizar la confidencialidad, la integridad y la disponibilidad de la información.

Herramientas de depuración incluidas en el entorno de desarrollo móvil

En Android Studio se encuentran, entre otras:

Herramienta Para qué sirve
Logcat Muestra los mensajes del sistema y de la app (Log.d, Log.e, etc.) y los errores con su traza. Se puede filtrar por nivel o etiqueta.
Depurador (Debugger) Permite poner puntos de interrupción (breakpoints), ejecutar paso a paso (step over, step into, step out), ver y modificar variables, y evaluar expresiones.
Emulador (AVD) Simula dispositivos con distintas versiones de Android, tamaños de pantalla y condiciones (red, batería, ubicación, sensores).
Layout Inspector Muestra la jerarquía de vistas de la pantalla en ejecución para detectar problemas de diseño.
Profiler Mide uso de CPU, memoria, red y energía para encontrar fugas de memoria y cuellos de botella.
Database Inspector Permite ver y consultar las bases de datos SQLite/Room de la app mientras corre.
Network Inspector Muestra las peticiones de red (URL, respuesta, tiempos).
ADB (Android Debug Bridge) Herramienta de línea de comandos para comunicarse con el dispositivo: instalar apps, ver logs, copiar archivos.
Lint Análisis estático que detecta posibles errores, problemas de rendimiento y de seguridad sin ejecutar la app.
Pruebas (JUnit, Espresso) Pruebas automáticas para encontrar errores antes de publicar.

En Xcode (iOS) existen herramientas equivalentes: consola de depuración, breakpoints, View Debugger, Instruments (rendimiento y memoria) y el simulador.

Ejemplo: usar Logcat

Log.d("Login", "Usuario ingresó: " + usuario)   // depuración
Log.i("Login", "Inicio de sesión correcto")      // información
Log.w("Login", "Contraseña muy corta")           // advertencia
Log.e("Login", "Error de conexión", excepcion)   // error

Ejemplo: pasos para usar un breakpoint

  1. Hacer clic en el margen izquierdo de la línea de código para poner un punto rojo.
  2. Ejecutar la app con el botón Debug (el ícono del insecto).
  3. Cuando la ejecución llegue a esa línea se detiene; revisar las variables en el panel inferior.
  4. Avanzar con Step Over (F8) o Step Into (F7), o continuar con Resume.

Buenas prácticas de seguridad

  • Usar HTTPS en todas las comunicaciones con servidores.
  • No guardar contraseñas ni datos sensibles en texto plano; usar EncryptedSharedPreferences o Android Keystore.
  • Pedir solo los permisos que realmente se necesitan.
  • No dejar claves de API ni credenciales escritas directamente en el código.
  • Validar siempre los datos que escribe el usuario.
  • Activar la ofuscación y optimización del código con R8/ProGuard en la versión de publicación.
  • Usar autenticación segura (tokens, OAuth, biometría) y cerrar sesión cuando expiren.
  • Mantener actualizadas las librerías para corregir vulnerabilidades.
  • Quitar los mensajes de Log con información sensible antes de publicar la app.
