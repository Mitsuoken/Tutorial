Definición

Un servicio en una aplicación móvil es un componente que realiza trabajo sin mostrar una pantalla al usuario, por ejemplo descargar archivos, reproducir música o sincronizar datos. Las notificaciones son mensajes que la app muestra fuera de su interfaz (en la barra de estado y el panel de notificaciones) para informar o avisar al usuario de algo, incluso cuando la app no está abierta.

¿Qué son las tareas en segundo plano?

Son procesos que se ejecutan sin que el usuario interactúe con ellos y sin bloquear la pantalla principal. Sirven para operaciones largas o periódicas: sincronizar información, subir fotos, descargar archivos, enviar datos al servidor o revisar nuevos mensajes.

Todo el trabajo pesado debe hacerse fuera del hilo principal (UI thread); si no, la app se congela y Android puede mostrar el error "La aplicación no responde" (ANR).

Herramienta (Android) Uso
Hilos y corrutinas de KotlinTareas cortas mientras la app está abierta.
ServiceComponente que corre tareas sin interfaz (música, descargas).
Servicio en primer plano (Foreground Service)Tareas que el usuario debe notar (reproducir música, navegación GPS). Muestra una notificación permanente.
WorkManagerTareas diferibles y garantizadas, aunque la app se cierre o el equipo se reinicie (sincronizar, subir registros).
AlarmManagerTareas a una hora exacta (alarmas, recordatorios).
JobSchedulerTareas programadas según condiciones (Wi-Fi, carga de batería).
Nota: las versiones modernas de Android limitan mucho lo que una app puede hacer en segundo plano para ahorrar batería. Por eso se recomienda WorkManager para la mayoría de las tareas diferibles.

Tratamiento de notificaciones en aplicaciones móviles

Tipos de notificaciones:

  • Locales: las genera la propia app en el dispositivo (recordatorios, temporizadores, alarmas).
  • Push (remotas): las envía un servidor a través de un servicio como Firebase Cloud Messaging (FCM) en Android o APNs en iOS (mensajes nuevos, promociones).

Elementos importantes en Android:

  • Canal de notificación (NotificationChannel): obligatorio desde Android 8. Agrupa las notificaciones por tipo y el usuario puede configurarlas.
  • Contenido: ícono pequeño, título, texto, y opcionalmente imagen, botones de acción y barra de progreso.
  • PendingIntent: define qué pasa cuando el usuario toca la notificación (abrir una pantalla).
  • Permiso de notificaciones: desde Android 13 se debe pedir al usuario el permiso POST_NOTIFICATIONS.
  • Importancia: define si la notificación hace sonido, vibra o aparece en pantalla.

Proceso de implementación

A) Proveedores de contenido (ContentProvider)

Un proveedor de contenido permite que una app comparta sus datos con otras aplicaciones de forma controlada, usando una URI (por ejemplo, los contactos o la galería del teléfono son proveedores de contenido).

  1. Crear una clase que herede de ContentProvider e implementar onCreate, query, insert, update, delete y getType.
  2. Definir la URI (autoridad) del proveedor, por ejemplo content://com.ejemplo.app.provider/tareas.
  3. Registrarlo en el AndroidManifest.xml con la etiqueta <provider> (y sus permisos).
  4. Desde otra parte de la app (o desde otra app con permiso) acceder con un ContentResolver.
// Consultar con ContentResolver
val cursor = contentResolver.query(
    Uri.parse("content://com.ejemplo.app.provider/tareas"),
    null, null, null, null
)

B) Tareas en segundo plano (ejemplo con WorkManager)

  1. Agregar la dependencia de WorkManager en build.gradle.
  2. Crear una clase Worker con el trabajo a realizar.
  3. Crear la solicitud (OneTimeWorkRequest o PeriodicWorkRequest) con restricciones opcionales.
  4. Enviarla a WorkManager para que la ejecute.
class SincronizarWorker(ctx: Context, params: WorkerParameters) : Worker(ctx, params) {
    override fun doWork(): Result {
        // Aquí va el trabajo pesado (descargar, subir datos, etc.)
        Log.d("Worker", "Sincronizando datos...")
        return Result.success()
    }
}

// Programar la tarea
val restricciones = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.CONNECTED)
    .build()

val trabajo = PeriodicWorkRequestBuilder<SincronizarWorker>(1, TimeUnit.HOURS)
    .setConstraints(restricciones)
    .build()

WorkManager.getInstance(this).enqueue(trabajo)

C) Notificaciones (ejemplo local)

  1. Declarar el permiso POST_NOTIFICATIONS en el manifest y pedirlo en ejecución (Android 13+).
  2. Crear el canal de notificación.
  3. Construir la notificación con NotificationCompat.Builder.
  4. Mostrarla con NotificationManagerCompat.
// 1. Crear el canal (una vez, por ejemplo al iniciar la app)
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
    val canal = NotificationChannel("canal_general", "General", NotificationManager.IMPORTANCE_DEFAULT)
    getSystemService(NotificationManager::class.java).createNotificationChannel(canal)
}

// 2. Construir la notificación
val intent = Intent(this, MainActivity::class.java)
val pendingIntent = PendingIntent.getActivity(this, 0, intent, PendingIntent.FLAG_IMMUTABLE)

val notificacion = NotificationCompat.Builder(this, "canal_general")
    .setSmallIcon(R.drawable.ic_notificacion)
    .setContentTitle("Recordatorio")
    .setContentText("Tienes una tarea pendiente")
    .setContentIntent(pendingIntent)
    .setAutoCancel(true)
    .build()

// 3. Mostrarla
NotificationManagerCompat.from(this).notify(1, notificacion)

Servicios de cómputo en la nube aplicables a la programación de apps móviles

La computación en la nube permite usar servidores, bases de datos y otros servicios por internet sin administrar la infraestructura propia. Para las apps móviles se usa en autenticación, almacenamiento, bases de datos, notificaciones push y lógica de servidor.

Servicio / plataforma Qué ofrece para apps móviles
Firebase (Google) Authentication, Firestore y Realtime Database, Cloud Storage, Cloud Messaging (notificaciones push), Cloud Functions, Analytics, Crashlytics.
Google Cloud Platform Máquinas virtuales, Cloud Run, Cloud Functions, bases de datos, almacenamiento.
Amazon Web Services (AWS) AWS Amplify, Cognito (usuarios), S3 (archivos), Lambda (funciones), DynamoDB, SNS (notificaciones).
Microsoft Azure App Service, Azure Functions, Notification Hubs, Cosmos DB, Blob Storage.
Otros (BaaS) Supabase, Appwrite, Back4App, entre otros.
